# Omnix Knowledge

Index attributed document chunks and retrieve relevant context using an explicit
embedding profile. Knowledge coordinates records, embedding providers and stores;
model execution belongs to Core and durable vector storage belongs to Storage.

The independent `omnix-knowledge` Rust crate is in `rust/backend`.
The Dart package wraps a separate native bridge and currently requires the
Flutter SDK.

## Rust integration

`KnowledgeIndex<S>` owns a `Store` and accepts an `Embedder` for text operations.
The base crate has no model or database dependency. Optional features add:

| Feature | Capability |
| --- | --- |
| `qdrant` | Persistent document records and vectors through Omnix Storage |
| `core-adapter` | Core embedding-provider adapters |
| `core-litertlm-embeddings` | The LiteRT tensor-based embedding adapter |
| `core-litertlm-embedding-engine` | The LiteRT-LM embedding-engine adapter |

`core-adapter` exposes the provider adapters but does not select an inference
runtime. When using it directly, also select a Core runtime in your dependency
configuration. The two LiteRT-specific features select their matching runtime
and embedding implementation explicitly.

Rust operations include `add_text`, `add_text_document`, `add_vector`,
`search_text`, `search_vector`, `remove` and `flush`. Text-document chunking
uses explicit character limits, not estimated model-token counts.

Records retain stable chunk and document IDs, content, source titles, optional
locations and public visibility. Profile identity and vector dimension must both
match. Your embedding provider must keep its profile stable throughout each
operation.

## Dart integration

Select Qdrant explicitly in the consuming application's build configuration:

```yaml
hooks:
  user_defines:
    omnix_knowledge:
      stores: [qdrant]
```

The standalone `OmnixKnowledgeIndex` API exposes `open`, `addVector`,
`searchVector` and `close`. Supply vectors generated by the matching embedding
provider; this package does not bundle a model runtime.

```dart
import 'package:omnix_knowledge/omnix_knowledge.dart';

Future<List<OmnixKnowledgeMatch>> searchPublicPassages({
  required String privateIndexPath,
  required String profileId,
  required List<double> queryVector,
}) async {
  final index = await OmnixKnowledgeIndex.open(
    path: privateIndexPath,
    profile: profileId,
    dimension: queryVector.length,
  );
  try {
    return await index.searchVector(queryVector);
  } finally {
    await index.close();
  }
}
```

Root Omnix can compose Core embedding execution with Knowledge for indexing,
retrieval and agent access through its system API. The standalone module example
is in `example/`.

## Access and durability

Access and score filters are applied before top-k ranking. The current standalone
Dart search returns public records only. Rust also exposes `LocalAll` for trusted
local callers; a remote request must not grant itself that scope.

The native Qdrant adapter stores record payloads and vectors together in a
dedicated embedding-profile namespace. Call `flush` to make accepted mutations
durable. Dropping a Rust index is not a flush guarantee; closing the Dart index
flushes it.

Multi-chunk document insertion is not one atomic transaction. If a store write
fails partway through, some chunks may already exist. Your application should
retain stable document identities and handle reindexing explicitly.

Embedding similarity is not a confidence probability. Raw-vector callers are
responsible for generating vectors from the declared embedding space.

## Host responsibilities

File picking, PDF/DOCX extraction, media capture and presentation belong in the
host application. Supply normalized text or compatible embeddings to Knowledge.
Core can run compatible multimodal embedding models, but that does not make the
standalone Dart index a file-upload or media-decoding API.

Choose a private storage directory and manage backups, retention and document
visibility. Stored payloads are not encrypted by the package.

## Test

Run from the repository root:

```sh
cargo test --manifest-path modules/omnix_knowledge/rust/backend/Cargo.toml --locked
cargo test --manifest-path modules/omnix_knowledge/rust/backend/Cargo.toml --locked --features qdrant
```

Contract tests use in-memory providers; Qdrant tests use disposable stores.
Real-model tests require explicit model/runtime inputs and may otherwise skip.
The APIs are a source-only developer preview; model and platform availability
depend on the selected provider and native packaging.
